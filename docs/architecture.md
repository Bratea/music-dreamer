## 2. 微服务拆分

| 服务名 | 端口 | 职责 |
|--------|------|------|
| gateway | 8080 | 统一入口、鉴权、限流、日志 |
| user-service | 8081 | 用户注册/登录/信息/关注 |
| song-service | 8082 | 歌曲CRUD、播放量统计、歌词 |
| playlist-service | 8083 | 歌单管理、收藏、推荐 |
| search-service | 8084 | ES全文检索、搜索建议 |
| song-process-service | 8085 | RabbitMQ 消费者（歌曲发布/删除/下架事件处理） |

## 3. 技术组件职责

### 注册与配置中心 (Nacos)
- 服务注册发现
- 统一配置管理（不同环境配置）
- 配置热更新

### 缓存 (Redis)
- 热点数据缓存（歌单、歌曲、用户信息）
- 播放量计数器（INCR + 定时持久化）
- 分布式锁（Redisson）
- 消息队列（Stream/List实现延迟队列）

### 搜索引擎 (Elasticsearch)
- 歌曲名/歌手/歌词全文检索
- 搜索建议（completion suggester）
- 搜索热词统计

### 认证 (JWT)
- Access Token（15分钟）
- Refresh Token（7天）
- Token黑名单（Redis存储）

### 限流降级 (Sentinel)
- Gateway层限流
- 服务间调用熔断
- 热点参数限流（热门歌曲）

## 4. 核心流程

### 4.1 用户收藏歌曲（分布式锁）

```
用户请求 → Gateway → 歌曲服务
                         │
                    Redisson.lock("collect:user:{userId}")
                         │
                   检查是否已收藏
                         │
                   写入 user_collect 表
                         │
                   歌曲收藏数 +1（Redis + 异步更新DB）
                         │
                   释放锁 → 返回结果
```

### 4.2 歌曲播放（异步统计）

```
用户请求播放 → Gateway → 歌曲服务
                           │
                      更新播放历史（写入 user_history）
                           │
                      歌曲播放量 Redis INCR +1
                           │
                      触发延迟任务（5分钟后持久化到DB）
                           │
                      更新热门歌曲缓存
                           │
                      返回音频流URL
```

### 4.3 搜索流程

```
用户输入 → Gateway → 搜索服务
                        │
                   ES multi_match查询
                   - 歌曲名
                   - 歌手名
                   - 歌词片段
                        │
                   高亮显示 → 返回结果
```

## 5. 推荐系统设计

### 推荐维度

| 场景 | 策略 | 实现 |
|------|------|------|
| 热门推荐 | 播放量TopN | Redis Sorted Set |
| 个性化推荐 | 基于用户历史 | 用户标签匹配 |
| 相似推荐 | 基于歌曲标签 | 标签权重计算 |
| 每日推荐 | 轮播热门 | 定时任务 |

### 推荐算法（进阶）

- **协同过滤**: 基于用户/物品的协同过滤
- **内容推荐**: 基于歌曲标签、流派、语言
- **混合推荐**: 多种策略加权融合

## 6. 数据同步

- MySQL → ES: Canal监听binlog异步同步
- 缓存更新: 写操作先更DB，再删缓存
- 播放量同步: 定时任务批量持久化
